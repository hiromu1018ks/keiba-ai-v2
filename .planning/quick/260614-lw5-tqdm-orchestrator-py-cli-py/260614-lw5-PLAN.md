<objective>
Add a tqdm progress bar to the scrape pipeline so an operator running a long
live batch can see live progress (count/%, rate, ETA) on stderr — the same
stream loguru already uses. Keep everything else output-neutral: existing
tests must stay green, and the flag must be off-able for log-file / CI use.

Purpose: Operability. A multi-race scrape currently emits only loguru INFO
lines; there is no single at-a-glance progress surface. tqdm gives that
without changing any data output.

Output: tqdm added as an explicit runtime dep; `run_scrape`/`_fetch_and_parse`
gain a `progress: bool = True` param; `scrape` CLI gains `--no-progress`;
tests updated to keep green and assert output-neutrality + flag wiring.
</objective>

     - Change `for ref in refs:` → `for ref in iterable:`.

     IMPORTANT details (the user flagged these):

     - When `max_races` truncates, tqdm renders N items done against a `total` of the full count, so the bar visibly stops short and the postfix explains why ("smoke N/total"). Do NOT manually close/set leave — let tqdm's defaults handle it (tqdm leaves the bar by default on completion).
     - tqdm MUST write to `file=sys.stderr`. tqdm auto-hides when stderr is not a TTY (piped / captured), so the existing tests are safe once they pass `progress=False` (Task 3).
