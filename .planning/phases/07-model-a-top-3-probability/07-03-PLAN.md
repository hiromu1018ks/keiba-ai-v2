<objective>
race_id グループ化 + race_date 時系列順で fold 境界を切る GroupTimeSeriesSplit（sklearn BaseCrossValidator 準拠）を実装する。sklearn 標準 TimeSeriesSplit は行単位で分割するため同一レースの馬が別 fold に割れ、Phase 8 Harville 計算時にレース内 p_top3 整合性が崩れる問題（D-03 根拠）を構造的に解消する。

**Codex HIGH #1 fix (07-03 fold-0 empty train):** 旧アルゴリズムは `_compute_fold_sizes` で `n_splits` 個の chunk を作り fold 0 の train = chunks[:0] = 空 になる構造的バグがあった。新アルゴリズムは `n_splits + 1` chunks（chunk 0 = warm-up train, chunks 1..n_splits = 各 fold の validation）を採用し、fold i の train = chunks 0..i（cumulative/warm-up 常に含む）・val = chunk i+1 とする。これで fold 0 も warm-up chunk を train として持ち、空 train が起きない。

**Cycle-2 HIGH #1 fix (temporal-order assertion dead code):** Codex Cycle 2 review は splitter の per-fold temporal-order assertion が「X が DataFrame で race_date 列を持つ場合」にのみ発火し、trainer が X=df[feature_columns]（race_date ∈ drop_columns）を渡すため実行 path で常に skip される dead code であることを指摘した。修正: split(X, y, groups, dates=None) シグネチャで **dates を明示的引数**として受け取る。dates が渡された場合（pandas Series / numpy array / list）、per-fold で `assert max(dates[train_idx]) < min(dates[val_idx])` を必ず実行する（X 列の有無に依存しない）。dates が None の場合は後方互換のため X が DataFrame で race_date 列を持つなら assertion を実行（従来動作）。trainer.collect_oof_predictions（07-04）は常に dates=df["race_date"] を渡すため、本番実行 path で assertion が発火することが保証される。

**[Cycle-3 HIGH fix — date-block-aware chunking]** Codex Cycle 3 review は Cycle-2 HIGH #1 fix で assertion が本番 path で live になったことで、race-count ベースの chunking が実データで必ず strict `<` assertion 違反を起こし本番 5-fold run を halt させる実行停止欠陥（[HIGH|new]）を指摘した。オーケストレータが実データ `data/feature/features_train.parquet` で独立検証: 23,288 training races / 1,236 unique dates・平均 30.75 レース/日・最小10・最大36・**単一レースの race_date はゼロ**。JRA では複数レース/日が普遍（エッジケースでない）。race-count chunking が 6 chunks を作ると内部 5 境界の少なくとも1つが日付内に落ち、`max(train_dates) == min(val_dates)` となり strict `<` assertion が AssertionError を raise する。**修正: chunking を date-block-aware にする** — まず ordered unique `race_date` 配列を作り、その date 配列を n_splits+1 個の date-block chunk に分割し（各 chunk は date の完全なブロック・日付をまたがない）、各 date-block chunk を展開してその date に属する全 race_id を得る。これで同一 race_date が train/val 境界をまたぐことが構造的に起きず、`max(train_dates) < min(val_dates)` は genuine invariant となり assertion は決して raise しない（latent landmine でなく真の不変条件）。Codex Cycle-1 suggestion「Optionally block same-race_date into the same time block」を完全実装する。n_splits=5 と n_splits+1=6 chunks の数は不変。warm-up chunk 0 が十分な date-block を持つよう `_compute_date_block_sizes` は base = n_dates // (n_splits+1) で計算し、base が 0 にならないよう ValueError で下限を検査する。
