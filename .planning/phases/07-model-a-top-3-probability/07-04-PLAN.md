<objective>
LightGBM 二値分類器（target_top3）の fold 学習・OOF 収集・全量再学習を行う trainer モジュールを実装する。RESEARCH.md Pitfall #1（early_stopping callback API・LightGBM 4.x で fit() の early_stopping_rounds は削除済み）と Open Question #3（最終モデル = 全量再学習の単一モデル・D-15 契約）をエンコードする。

**Codex HIGH #2 fix (OOF row count):** 旧仕様は「OOF rows == input rows」を要求したが、expanding-window CV（n_splits+1 chunks）は定義上 warm-up chunk 0 の行に OOF 予測を生成できない。warm-up に予測を強制すれば in-sample 予測になり Isotonic キャリブレーションがリークする。新仕様: OOF 行数 = validation chunks（chunks 1..n_splits）の行数の合計。warm-up chunk 0 は OOF・キャリブレーションから除外する。

**Codex HIGH #3 fix (07-04 depends on 07-03):** 07-04 は `split_train_validation` を lazy import していたが、lazy import は file-write conflict を避けるだけで並列実行可能性は生まない。07-04 を wave 2 に移動し depends_on に 07-03 を追加する（07-03 完了後に 07-04 が実行される）。

**Codex HIGH #5 fix (feature_columns config key):** 旧仕様は `config["data"]["feature_columns"]` を参照したが 07-07 の YAML に同キーが存在せず KeyError になる。新仕様: `feature_columns` を collect_oof_predictions と train_final_model の明示的引数にする。

**Codex HIGH #6 fix (train_final_model full retrain):** 旧 train_final_model は末尾 20% を early-stopping val に切り出し ~80% で学習したモデルを返していた（D-15/Open-Question-#3 の「全量再学習」違反）。新仕様: 二段階学習 — Stage 1 で validation split で best_iteration を決定、Stage 2 で全 2018-2024 行を best_iteration まで再学習して真の全量モデルを返す。

**Cycle-2 HIGH #1 fix (temporal-order assertion always fires):** Codex Cycle 2 review は splitter の per-fold temporal-order assertion が trainer で dead code になることを指摘した（trainer が X=df[feature_columns] を渡し race_date は feature_columns に含まれないため）。修正: collect_oof_predictions は splitter.split(X, y, groups=race_ids, **dates=df["race_date"]**) を呼ぶ。dates は 07-03 の明示的引数で、渡されれば per-fold max(train_dates) < min(val_dates) が常に assert される（X 列の有無に依存しない）。前提: load_features（07-02）が train_df に race_date 列を保持したまま返すこと（drop しない）。trainer 内部で race_date を drop してはならない。

Purpose: MODA-01「LightGBM による3着内確率モデルを構築し各馬の p_top3 を出力」の中核。sensible defaults + early stopping（D-13）で過学習を抑えた安定モデルを作る（CLAUDE.md「まず確実に進める」哲学）。OOF 予測はキャリブレーション(07-05)の学習データになる。
