    Implement `compute_jockey_trainer_stats(df: pd.DataFrame) -> pd.DataFrame`:

    The key architectural decision (addressing review concern #4) is to compute person stats at the **race level**, not the row level:

    **Step 1: Aggregate to race-level person outcomes.**
    For each (person_col, race_id) pair, compute:
    - `race_is_top3`: any horse ridden by this person finished top 3 (max of is_top3 across runners in same race)
    - `race_is_win`: any horse ridden by this person won (max of is_win across runners in same race)
    - `race_n_runners`: count of horses this person had in this race (for trainers with multiple runners, this is >1)
    - `race_date`: the date of this race

    Create a person-race level DataFrame with one row per (person, race_id).

    **Step 2: Sort person-race data by race_date.**
    For each person, sort their race-level data chronologically.

    **Step 3: Apply D-08 constraint per row (exact intersection).**
    For each row in the person-race DataFrame, the eligible prior races satisfy BOTH:
    - Condition A: `race_date >= current_race_date - timedelta(days=365)`
    - Condition B: among the most recent 100 prior valid starts (where "valid start" means the person actually ran -- exclude scratches/removals)

    Implementation approach:
    - Compute expanding-window stats from all prior data (shift(1) applied)
    - Compute rolling(100) stats
    - For each row, count prior rides within 365 days
    - Select whichever constraint yields fewer observations:
      - If expanding count > 100 AND 365-day count > 100: use rolling(100) stats
      - If expanding count <= 100 AND 365-day count >= expanding count: use expanding stats
      - If 365-day count < expanding count AND 365-day count <= 100: use only the 365-day window stats
    - For the 365-day constraint: recompute stats using only rows where race_date >= current_date - 365 days

    Practical optimization: pre-compute expanding and rolling(100) stats, then apply a 365-day mask as a post-processing step. For 311K rows, the per-row loop for 365-day filtering is feasible because it operates on the person-race level (much fewer rows than entry level -- each trainer/jockey has at most a few hundred races).

    Helper function `_compute_person_stats(df, person_col, prefix)`:
    - Takes entry-level df, person column name, and prefix string ("jockey" or "trainer")
    - Aggregates to race level as described
    - Computes expanding and rolling(100) stats with shift(1)
    - Applies 365-day constraint
    - Returns df with 3 new columns: {prefix}_rolling_top3_rate, {prefix}_rolling_win_rate, {prefix}_rolling_rides

    **Valid start definition (addressing review concern about denominator):**
    - Valid start: result_status is NOT in ["scratched", "removed"] (the horse actually ran)
    - DNF/disqualified count as valid starts (they ran, per D-13 they are included in training)
    - Only scratched/removed entries are excluded from ride counts
