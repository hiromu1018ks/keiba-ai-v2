Implement temporal-safe lag features (45 columns) with valid-start filtering, and jockey/trainer rolling statistics (6 columns) with sum-based race-level aggregation and exact D-08 intersection.

Purpose: Lag features encode each horse's recent performance history. Jockey/trainer stats capture human-factor signals. Both require strict temporal safety. This plan fixes three root causes: (1) scratched entries no longer corrupt lag positions, (2) trainer stats use sum-based rates not binary any(), (3) D-08 uses exact intersection of 365-day AND 100-ride constraints.

    **Valid-start filtering -- the fix for scratched entries consuming lag positions:**

    The problem: `groupby("horse_entity_key").shift(n)` operates on ALL rows including scratches. If a horse has valid_start, scratched, valid_start, then shift(1) on row 3 points to the scratched row (all NaN) instead of the actual prior valid start.

    The fix: Before computing lags, create a boolean `is_valid_start` column:
    ```
    is_valid_start = (
        df["finish_position"].notna()   # Has a finish position (normal finish, DNF, demoted, disqualified)
        | df["finish_note"].isin(["中", "失"])  # DNF/disqualified -- started but didn't finish normally
    )
    # Excluded: 取 (scratched), 除 (removed) -- they never started the race
    ```
    Note: finish_note "取" and "除" have finish_position=NA and finish_time=None. finish_note "中" and "失" also have finish_position=NA but they DID start the race -- their last_3f/corner_4 may be partially available.

    Actually, examining the data: 取 (520 rows), 除 (604 rows) have finish_position=NA and finish_time=None. 中 (966 rows) also has finish_position=NA. For lag feature purposes, "valid start" means the horse actually ran in the race:
    - 取 (scratched): did NOT run. Exclude from valid starts.
    - 除 (removed): did NOT run. Exclude from valid starts.
    - 中 (DNF): DID run but did not finish. Include as valid start (has partial data).
    - 失 (disqualified): DID run. Include as valid start.
    - 降 (demoted): DID run. Include as valid start.
    - Normal finishes: Include as valid start.

    So: `is_valid_start = ~df["finish_note"].isin(["取", "除"])`
    (Only 取 and 除 are excluded. Everything else ran.)

    **Implementation of compute_lag_features(df):**

    Step 1: Create is_valid_start column.
    Step 2: Filter to valid-start rows only: `valid_df = df[is_valid_start].copy()`
    Step 3: Compute lag features on valid_df:
    - Sort valid_df by [horse_entity_key, race_date, race_id] (deterministic order)
    - For each metric in [finish_position, last_3f, corner_4, finish_time_zscore, margin_numeric]:
      - For lag in 1..5: `valid_df[f"prev_{lag}_{metric}"] = valid_df.groupby("horse_entity_key")[metric_col].shift(lag)`
    - Compute 3-race and 5-race statistics on the lag values:
      - For each metric: prev3_{metric}_mean = rolling(3, min_periods=1).mean() of prev_1_{metric} grouped by horse_entity_key
      - prev3_{metric}_std = rolling(3, min_periods=2).std() of prev_1_{metric}
      - Same for prev5 with rolling(5)
    Step 4: Select only the lag+stat columns plus the merge keys (race_id, horse_race_id or similar unique row identifier) from valid_df.
    Step 5: Left-merge back to the full df on the merge keys. Invalid-start rows get all-NaN lags (correct).

    The 5 lag metrics per D-02: finish_position, last_3f, corner_4, finish_time_zscore, margin_numeric.
    Total: 25 raw lag + 20 stat = 45 columns.

  <action>
    **Sum-based race-level aggregation -- the fix for trainer stat semantics:**

    The problem: `any(top3)` at race level produces 1 if ANY runner finished top-3. A trainer with 2/3 runners in top-3 gets the same "1" as one with 1/1.

    The fix: For each (person, race_id), compute:
    - `top3_count`: number of runners that finished top-3 (sum of is_top3 across runners)
    - `win_count`: number of runners that won (sum of is_win)
    - `valid_start_count`: number of runners that actually started (excludes 取/除)

    Rolling rates = rolling_sum(top3_count) / rolling_sum(valid_start_count).

    **Exact D-08 intersection -- the fix for "choose smaller of two stats":**

    The problem: The previous approach computed two separate stats (expanding and rolling(100)) and picked whichever had fewer observations. This is NOT the same as computing stats over the intersection.

    The fix: For each person-race row, compute stats over the exact set of prior valid starts that satisfy BOTH:
    - Condition A: race_date >= current_race_date - 365 days
    - Condition B: among the most recent 100 prior valid starts

    Implementation approach (O(n) per person with sorted data):

    Helper `_compute_person_stats(df, person_col, prefix)`:

    Step 1: Create entry-level boolean columns:
    - `is_top3`: finish_position <= 3 and finish_position not NA
    - `is_win`: finish_position == 1
    - `is_valid_start`: ~finish_note.isin(["取", "除"]) (same as lag feature definition)

    Step 2: Aggregate to person-race level (one row per person per race):
    ```
    person_race = df.groupby([person_col, "race_id"]).agg(
        top3_count=("is_top3", "sum"),
        win_count=("is_win", "sum"),
        valid_start_count=("is_valid_start", "sum"),
        race_date=("race_date", "first"),
    ).reset_index()
    ```
    Sort by [person_col, race_date, race_id].

    Step 3: For each person, iterate their races chronologically. Maintain a list of prior valid starts (top3_count, win_count, valid_start_count, race_date). For each new race:
    - Remove entries where race_date < current_date - 365 days
    - Keep at most the most recent 100 entries (by position in the list -- they're already sorted by date)
    - Compute: sum(top3_count), sum(win_count), sum(valid_start_count) over the remaining entries
    - Rate = sum(top3_count) / sum(valid_start_count) (NaN if denominator is 0)
    - Rides = sum(valid_start_count)

    Implementation using pandas vectorized operations where possible:
    - For each person, build their chronological race list
    - Use a deque/list that gets trimmed from the front (too old) and back (too many)
    - Accumulate running sums to avoid recomputation

    Alternative practical approach (simpler, still correct): For each person's row i, use iloc to select rows 0..i-1, filter to date range, take last 100, sum. This is O(n^2) per person but acceptable because: (a) per-person data is small (hundreds of rows, not 311K), (b) there are ~300 jockeys and ~400 trainers, (c) total iterations ~30K (311K entries / ~10 avg per person).

    Step 4: Merge person-race stats back to entry-level df on (person_col, race_id). All runners of the same person in the same race get identical stats.

Tests 8-10 verify the D-08 exact intersection with constructed data.
