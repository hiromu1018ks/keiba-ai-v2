**Out of scope:**
- Model Aの学習・予測（Phase 7）

<decisions>
## Implementation Decisions

### 近走成績のlag feature設計
- **D-01:** lag遡り範囲は **3レース + 5レースの両方** を生成。モデルが重要な方を使用
- **D-02:** lag対象指標は5指標（拡張セット）:
  - `finish_position` — 直近の着順
  - `last_3f` — 上がり3ハロンタイム
  - `corner_4` — 4コーナー通過順位
  - `finish_time` — タイム（コース×距離のz-score正規化済み）
  - `margin` — 着差（数値変換済み）
- **D-03:** finish_timeは **コース×距離別のz-score** で正規化。各コース×距離の平均・標準偏差を計算し、偏差に変換
- **D-04:** marginは **数値変換マッピング** で処理（Claude's Discretion: `1.1/4`→1.25, `大`→大幅等の具体的マッピングを定義）
- **D-05:** lag形式は **lag生値 + 統計量**:
  - lag生値: `prev_1_*` 〜 `prev_5_*`（各指標×5レース分）
  - 3走統計量: 近3走の平均・標準偏差
  - 5走統計量: 近5走の平均・標準偏差

### 騎手・調教師の特徴量化
- **D-06:** LightGBMの **native categoricalとして直接投入** + **rolling統計量** の両方
- **D-07:** 統計量は基本3指標:
  - 3着内率（p_top3に直結）
  - 勝率（1着率）
  - 騎乗数（サンプル信頼性の指標）
- **D-08:** 統計量の計算期間は **直近100戦または直近1年間の短い方**。当該レースより前のデータのみ使用（時系列リーク防止）

### 初出走馬の扱い
- **D-09:** lag featureは **NaNのまま** + **is_debut ブール特微量** を追加。LightGBMがNaNをnative処理しつつ、明示的なデビュー信号も伝える
- **D-10:** 出走数が3走/5走未満の馬は **可能な分だけ統計量を計算**（例: 2走なら2走で平均を出す）。不足分はNaN

### Target変数と評価設計
- **D-11:** **target_top3** 列を学習用feature Parquetに含める。予測用には含めない設計で、学習/予測を区別
- **D-12:** target_top3の定義:
  - 正式着順 1〜3着 → `target_top3 = 1`
  - 正式着順 4着以下 → `target_top3 = 0`
  - 同着で3着以内に含まれる馬 → `target_top3 = 1`
  - 降着・失格がある場合は最終確定後の公式着順を基準
- **D-13:** 未完走馬の取り扱い:
  - 取消(取)・除外(除)・発走除外 → **学習対象から除外**
  - 競走中止(中)・失格(失)等（出走したが完走せず）→ `target_top3 = 0`、学習対象に含む
- **D-14:** 補助列 `result_status` / `is_dnf` を残して後から分析可能にする

### 人気・単勝オッズの除外（Phase 1からの引き継ぎ）
- **D-15:** 人気・単勝オッズはfeature層では使用しない（Phase 1 D-03/D-06: post-race扱い）。純粋に馬・レース特性のみで3着内確率を予測し、EV計算で初めてオッズと比較する構図を守る

### Claude's Discretion
- finish_timeのz-score正規化の具体的実装（コース×距離の平均・標準偏差の計算方法）
- marginの数値変換マッピング（`1.1/4`→1.25, `大`→大幅等の詳細テーブル）
- lag featureの生成方法（`.shift(1)`による時系列安全なlag、groupby horse_name等の具体的pandas操作）
- feature Parquetのファイル構成（単一ファイル vs テーブル別等）
- 統計量計算のrolling window実装詳細
- result_status/is_dnf補助列の具体的な値定義
- categorical列のCategoricalDtype変換の実装

</decisions>

<specifics>
## Specific Ideas

- **学習/予測の区別設計**: feature生成パイプラインは学習用と予測用で共通だが、target_top3列は学習用Parquetにのみ含める。予測時（当週レース）にはresultデータが存在しないため、target生成ステップをスキップする設計にする
- **result_status補助列の目的**: 「出走したが完走しなかった」馬（中止・失格等）を後から分析できるようにする。例えば「中止馬を除外した場合と含めた場合でモデル精度がどう変わるか」を検証可能にするため
- **5指標×3/5走の特微量数**: lag生値（5指標×5 = 25列）+ 3走統計量（5指標×2 = 10列）+ 5走統計量（5指標×2 = 10列）= **45列**の近走成績特微量。LightGBMにとっては妥当な規模
- **lag featureの時系列安全性**: 同一馬の過去レースを`race_date`でソートし、`.shift(1)`で1レース前の値を参照。現在レースのresult情報は一切使用しない

</specifics>
