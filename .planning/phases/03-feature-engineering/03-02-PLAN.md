  <action>
    Implement `parse_finish_time_to_seconds(time_str: str) -> float`:
    - If None or NaN, return np.nan
    - Split on ":" to get minutes and seconds
    - Return float(minutes) * 60 + float(seconds)
    - Handle edge case where format is missing ":" (return np.nan)

    Implement `compute_finish_time_zscore(df: pd.DataFrame) -> pd.DataFrame`:
    - First, create finish_time_seconds column by applying parse_finish_time_to_seconds to "finish_time"
    - Compute global mean and std per (course_name, distance) group:
      `cd_stats = df.groupby(["course_name", "distance"])["finish_time_seconds"].agg(["mean", "std", "count"])`
    - For combos with count < 30: set mean and std to NaN (per RESEARCH.md Pitfall 5)
    - Merge cd_stats back to df on (course_name, distance)
    - Compute finish_time_zscore = (finish_time_seconds - mean) / std
    - Drop the temporary mean/std/count columns
    - Return df with finish_time_seconds and finish_time_zscore added

    Per RESEARCH.md A2: Using global stats (not expanding window) is acceptable for normalization. This is documented as a known assumption.

    Wire into generate() orchestrator: call compute_finish_time_zscore() after convert_margin_to_numeric().

    Update sample_standard_result_df fixture if needed to ensure it has multiple rows in same course-distance group for z-score testing (the fixture from Plan 01 should already cover this since it has 4 entries for race 201501010101 at 東京2000).
