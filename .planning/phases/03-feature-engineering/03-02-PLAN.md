## Review Feedback Addressed

| Concern | Severity | How Addressed |
|---------|----------|---------------|
| Global z-score temporal leakage | HIGH | compute_finish_time_zscore() uses expanding-window mean/std per (course_name, distance, surface) group sorted by race_date, with shift(1) to exclude current row. No global stats computed. |
| Z-score grouping only by course+distance may mix surface types | MEDIUM | Grouping key expanded to (course_name, distance, surface) to separate turf and dirt races at same course-distance |
| std==0 edge case for sparse groups | MEDIUM | When expanding std is NaN or 0, z-score is set to NaN with explicit guard |

  <action>
    Implement `parse_finish_time_to_seconds(time_str: str) -> float`:
    - If None or NaN, return np.nan
    - Split on ":" to get minutes and seconds
    - Return float(minutes) * 60 + float(seconds)
    - Handle edge case where format is missing ":" (return np.nan)

    Implement `compute_finish_time_zscore(df: pd.DataFrame) -> pd.DataFrame`:
    - df is already sorted by SORT_KEY from load_and_merge()
    - Create finish_time_seconds column by applying parse_finish_time_to_seconds to "finish_time"
    - Sort within each (course_name, distance, surface) group by race_date to ensure chronological order within groups
    - Group by ["course_name", "distance", "surface"] and compute expanding-window statistics:
      - For each group, compute expanding mean with shift(1):
        `grp["finish_time_seconds"].expanding(min_periods=5).mean().shift(1)`
      - Similarly for expanding std with shift(1)
      - The shift(1) ensures the current row's finish_time does NOT contribute to its own normalization stats
      - min_periods=5 means rows without at least 5 prior observations get NaN stats (sparse group guard per review concern)
    - When expanding std is NaN or 0, set z-score to NaN (guard against inf)
    - Compute finish_time_zscore = (finish_time_seconds - expanding_mean) / expanding_std
    - The expanding window approach guarantees temporal invariance: only prior races in the same group contribute to the normalization parameters
    - Add finish_time_seconds and finish_time_zscore to df
    - Return df

    **Why expanding-window instead of global stats:** Global mean/std computed from all data (including future races) leaks information about future race distributions into historical rows. Even though the model sees normalized values, the normalization parameters themselves carry future information. Expanding-window with shift(1) is the correct temporal-safe approach.

    **Why group by (course_name, distance, surface):** Different surfaces (turf vs dirt) at the same course-distance have materially different speed profiles. Including surface in the grouping key prevents mixing incompatible race types.

    Wire into generate() orchestrator: call compute_finish_time_zscore() after convert_margin_to_numeric().
