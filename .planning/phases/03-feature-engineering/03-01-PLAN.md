## Review Feedback Addressed (Cycle 3 -- Root Cause Fix)

| # | Concern | Severity | Root Cause | Fix |
|---|---------|----------|------------|-----|
| 1 | horse_key surrogate logically flawed | HIGH | `horse_name + first_race_date` collapses same-name horses via groupby("horse_name").transform("min"). Two different horses named "アームストロング" born 2011 vs 2018 get the same first_race_date if they happen to debut near each other -- or worse, the transform gives ALL rows the same min date. | Use `horse_name + birth_year_proxy` where `birth_year_proxy = race_year - age`. Verified: this disambiguates all 14 name collisions in 2015-2021 data (109 rows). Data analysis: 36,816 unique entities vs 36,802 unique names. |
| 7 | Race ordering not globally unique | HIGH | (horse_key, race_date, race_number) not unique across courses -- Tokyo Race 5 and Nakayama Race 5 on same day collide. | SORT_KEY = [horse_entity_key, race_date, race_id]. race_id encodes course+date+number (format YYYYPPCCDDRR) and is globally unique. Verified: (race_date, race_number, course_name) is unique in data. |
| 6 | Resultless rows cannot distinguish scratched from removed | HIGH | Previous plans assumed left-join needed because scratched entries might lack result rows. | Data analysis reveals: entry and result are 1:1 at 311,806 rows each. EVERY entry has a result row. finish_note column distinguishes 取 (scratched, 520 rows), 除 (removed, 604 rows), 中 (DNF, 966 rows), 降 (demoted, 18), 失 (disqualified, 1). Inner join is correct. |

    Implement `derive_horse_entity_key(df: pd.DataFrame) -> pd.DataFrame`:
    - Takes merged DataFrame with horse_name, age, race_id columns
    - Extract race_year from race_id: `df["race_year"] = df["race_id"].str[:4].astype(int)`
    - Compute birth_year_proxy: `df["birth_year_proxy"] = df["race_year"] - df["age"]`
    - Create horse_entity_key: `df["horse_entity_key"] = df["horse_name"] + "_" + df["birth_year_proxy"].astype(str)`
    - This produces keys like "アームストロング_2011" and "アームストロング_2018" for two different horses sharing the name
    - Verified: 36,816 unique (horse_name, birth_year_proxy) pairs in 2015-2021 data, vs 36,802 unique horse_names. The 14 collision names (109 rows) are correctly split.
    - Drop the intermediate birth_year_proxy column (not needed downstream)
    - Return df with horse_entity_key column added

    Implement `load_and_merge(standard_dir: Path) -> pd.DataFrame`:
    - Read race.parquet, entry.parquet, result.parquet via pd.read_parquet with pyarrow engine
    - Merge: `df = entry.merge(race, on="race_id", how="left")` then `df = df.merge(result, on="horse_race_id", how="inner")`
    - Inner join on result is correct: data analysis confirms entry and result are 1:1 (311,806 rows each, zero IDs in one but not the other)
    - Call derive_horse_entity_key(df) to add the horse_entity_key column
    - Sort by SORT_KEY ["horse_entity_key", "race_date", "race_id"] and reset_index
    - race_id encodes course+date+number (format YYYYPPCCDDRR), making it globally unique. Verified: (race_date, race_number, course_name) is unique.
    - Return merged DataFrame

    Implement `extract_race_context_features(df: pd.DataFrame) -> pd.DataFrame`:
    - Computes field_size as df.groupby("race_id")["horse_number"].transform("count")
    - Returns df with guaranteed columns: race_id, race_date, course_name, distance, surface, direction, weather, track_condition, race_number, grade, field_size, horse_entity_key
    - Does NOT include popularity, win_odds, or any post-race result columns

    - Explicitly documents that popularity and win_odds are NOT extracted (per D-15, post-race)
