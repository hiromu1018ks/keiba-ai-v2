## Review Feedback Addressed

| Concern | Severity | How Addressed |
|---------|----------|---------------|
| horse_name entity key instability | HIGH | New `derive_horse_key()` function computes `horse_name + "_" + first_race_date` surrogate key; all lag/rolling operations use horse_key instead of horse_name |
| Non-deterministic race ordering | HIGH | Merge includes race_number from race table; sort key is `["horse_key", "race_date", "race_number"]` providing total ordering even for same-day same-course races |
| Merge drops resultless entries | HIGH | load_and_merge() uses LEFT join on result table, preserving scratched/removed entries that Plan 04 must classify |

    **feature_generator.py:**

    Follow the kaggle_converter.py structural pattern exactly. Module docstring documents all D-NN decisions and review fix rationale. Imports: pathlib.Path, pandas, numpy, loguru.logger, audit_leakage from src.schemas.audit, all 3 schema classes.

    Define SORT_KEY constant: `["horse_key", "race_date", "race_number"]`

    Implement `derive_horse_key(df: pd.DataFrame) -> pd.DataFrame`:
    - Takes merged DataFrame with horse_name and race_date columns
    - Compute first_race_date per horse_name: `first_dates = df.groupby("horse_name")["race_date"].transform("min")`
    - Create horse_key: `df["horse_key"] = df["horse_name"] + "_" + first_dates.astype(str)`
    - This creates a stable surrogate key: same-name horses debuting on different dates get different keys (defending against name collisions, which data analysis confirms are zero in 2015-2021 but the defense-in-depth is warranted per review concern)
    - Return df with horse_key column added

    Implement `load_and_merge(standard_dir: Path) -> pd.DataFrame`:
    - Read race.parquet, entry.parquet, result.parquet via pd.read_parquet with pyarrow engine
    - Merge: `df = entry.merge(race, on="race_id", how="left")` then `df = df.merge(result, on="horse_race_id", how="left")`
    - The LEFT join on result preserves entries without result rows (scratched/removed horses per review concern #6)
    - Call derive_horse_key(df) to add the horse_key column
    - Sort by SORT_KEY `["horse_key", "race_date", "race_number"]` and reset_index
    - race_number provides sub-day ordering (races at same course on same day run in sequence 1-12)
    - Validate merge cardinality: after each merge, assert no row duplication by checking len(df) equals expected count (entry count after race merge, unchanged after result left merge)
    - Return merged DataFrame

    Implement `extract_race_context_features(df: pd.DataFrame) -> pd.DataFrame`:
    - Takes the merged DataFrame
    - Computes field_size as df.groupby("race_id")["horse_number"].transform("count")
    - Returns df with guaranteed columns: race_id, race_date, course_name, distance, surface, direction, weather, track_condition, race_number, grade, field_size, horse_key
    - Does NOT include popularity, win_odds, or any post-race result columns

    Implement `extract_horse_basic_features(df: pd.DataFrame) -> pd.DataFrame`:

    - These are direct column selections from the entry table -- no transformation needed
    - Explicitly documents that popularity and win_odds are NOT extracted (per D-15, post-race)
