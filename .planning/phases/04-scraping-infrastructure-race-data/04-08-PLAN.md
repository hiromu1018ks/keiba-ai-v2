`https://db.netkeiba.com/race/calendar/{YYYYMM}/` does NOT contain racing-day
links on the live site — it returns ~40KB of navigation-only HTML with ZERO

`run_scrape(live=True)` produces empty output, completely blocking the phase
goal (scrape 2022-2024 real data).

real races. Live probing (performed during planning, NOT to be re-run by the
executor) confirmed the CORRECT URL form: `https://db.netkeiba.com/race/list/{YYYYMM}/`
(same path prefix as the per-day URL, just 6 digits instead of 8) returns
exactly the racing days for that month — verified to yield 8 days for 2023-06
and 8 days for 2023-02, with the SAME relative `/race/list/{8d}/` href shape
that `parse_calendar_month_html` already parses correctly.

The fix is therefore narrow: change ONE path segment (`calendar` -> `list`) in
`enumerate_race_day_urls`. The downstream parsing logic is unchanged because
netkeiba emits the identical relative href shape on both pages. The broader
fix is regression coverage: add a golden-fixture test that asserts the URL
contract against a real saved HTML snapshot so this can never silently regress.

`tests/scraper/test_enumeration.py` and `tests/scraper/test_end_to_end.py`;
